# 荷卸し検証・夜勤作業ガイド（LINE共用Webアプリ）

公開URL：https://yshimano-dev.github.io/fuel-check-night-web/

## 目的
一画面を縦スクロールしながら、ローリー到着からPOS帳票・手入力・数値判定・紙3枚保存までを進める非公式補助アプリ。
画像OCR・AI・外部送信は不使用。アプリ利用者の登録も不要。

## 進行順（実際のENEOS配布操作マニュアルに基づく）
1. ローリー到着直後、油面計の在庫レシートを印字。
2. 荷卸し前のタンク管理表を印字。ENERIS-POS: メインメニュー → 点検 → SS営業日報管理 → タンク管理表 → 当日分 → 印刷。
3. 荷卸し前タンク管理表の計算在庫Aと、前レシートの実在庫Bを順番に入力。
4. 正式な荷卸し作業手順で受け入れを行う。
5. 受け入れ完了直後、油面計の後レシートを再印字。
6. 権限ある担当者がPOS入庫処理後、荷卸し後のタンク管理表を印字。ENERIS-POS: 通常→入出荷業務→入庫→転受カード一覧→カード名称:入庫→担当者コード→商品パネル→油種選択→タンクNo→数量→単価削除・金額未入力。
7. 荷卸し後タンク管理表の計算在庫C、後レシートの実在庫D、今回入荷数量④を入力。
8. ①=B−A、②=D−C、③=②−①、誤差率=③/④ を自動判定。
9. 店舗の正式手順に従い、紙の荷卸し検証チェック表に手書き・前後帳票と3枚セットで保存。

## 仕様
- 伊都店の初期設定：No1=14KL H、No2=48KL R、No3=14KL D、No10=20KL K。
- 管理者が店舗名・タンク番号・容量・油種を正式登録する。1店舗20タンクまで、タンクNoは1〜30、同じ油種のタンクを複数登録可。POS種類の選択は登録・操作画面から外し、通常の案内では「ENEOS POS」と表記する。
- H/R/Dは±400Lまたは±2.5%、Kは±100Lまたは±2.5%のどちらか以上で×。他油種は店舗の正式基準を入力するまで「基準未設定」。
- ④=0のときは率を算出せず、数量誤差が基準以上なら×、それ以外は「入荷なし」。
- 未入力は「未入力」。数字だけを入力。iPhoneの数字キーボードを使用。
- 作業数字・入庫カード名称・選択番号・担当者コード・担当者ボタン名は各端末のブラウザに店舗別保存。現行版に店舗追加用LINE共有リンク機能はない。
- POS操作と紙記入の時点、誰がPOS操作可能かは店舗正式の運用を優先。数値○だけでローリーへの最終許可と見なさない。

## 運用・技術
- GitHub Pages上の静的Webアプリ。既存配達アプリと別のプロジェクト。
- 現場用の写真・ENEOSの原本PDF・個人のデータは公開サイトに含まない。
- 元資料：2026-10-15 ENEOS帳票操作マニュアル。POS21手順は同PDFの4〜9ページ、ENERIS-POSは12〜21ページ。
- 確認：node --test tests/calc.test.cjs と Edge + Playwright のスマホ幅390px実機相当画面テスト。
## 店舗を選んだ直後の操作フロー
- 店舗選択の直下に「受け入れ前」「受け入れ後」のPOS操作フローを表示。
- 伊都店では、入庫カード（表記は現場のPOSで確認）とカード一覧の選択番号2を初期設定。
- 担当者コードは公開ページに埋め込まず、作業者がその端末で初回のみ登録。以後は店舗専用フローとPOS入庫説明に表示。
- 入庫カード名と選択番号は店舗選択直下の「カードを変更・登録」から、担当者コード・担当者ボタン名は「店舗別に設定」から変更可能。一度保存すれば次回起動時に自動表示。
- LINEで共有する通常のアプリURLには、各端末の担当者指定情報・カード設定・帳票数字を含まない。
- 共用端末で担当者コードを保存しないこと。保存した値はブラウザのサイトデータを消去して削除できる。

## 画像付き操作補助（2026-11-02更新）
- 「映像で確認」ボタンをフロー上部・レシート印字・荷卸し前POS・入庫処理に追加。
- モーダル内の画面は、ユーザー提供ENEOSマニュアル（2026-10-15版）の操作順をもとに独自に作成した再現図。原本PDFの画面写真や実際の動画を公開サイトに載せていない。
- 店舗の操作フロー、入庫カード名・番号、担当者コードの表示と連動。担当者コードの保存先は各端末のみ。POS種別はユーザーに選ばせず、「映像で確認」内の別機種POS21参考画面からも操作手順を見られる。
- 追加で提供された6枚の写真はPOS21の「タンク管理レポート出力」と「燃料入庫（仕入）処理」。油面計レシート印字とは別の工程。参考画面は写真に記載された点検／問合せ→タンク管理→印刷→レシート出力、伝票入力→仕入→仕入先選択→エネオス→確定2回→タンクNo・数量→油種選択の順をもとに作成。
- 伊都店の油面計は「印刷」ボタン1回でレシートを出す案内にし、他店舗は機種固有手順を確認するよう表示。
- 原本PDFを夜勤内で共有する場合は、店舗の承認された経路で別途送付する。

## 紙へ転記用画面
- 工程9に原紙と同じ順番のA/B/C/D/①②③・誤差率・判定・④の横長表を追加。
- 表の見出し行と左3列（タンクNo.・容量・油種）をsticky固定。表の中を横/縦スクロールする。
- 「入力数字をクリア」を実行すると、確認ダイアログの後、作業数字・判定・進行チェックを消去。店舗設定・コード・タンク構成は保持。
- iPhone幅390px、Android幅360pxのブラウザ模擬テストに合格。実機確認は未実施。
- iPhone/AndroidともLINEに貼った同じURLからブラウザで使用し、インストール不要。

## 店舗の新規登録（管理者限定）
- 新規店舗の登録は公開Webページからできません。ブラウザの「別店舗を作る」「店舗を削除」「タンクを追加」「店舗設定共有リンクから登録」は廃止。
- 正式な店舗一覧は \`stores.js\` の \`FUEL_APPROVED_STORES\` で管理。追加・変更には GitHub リポジトリ \`yshimano-dev/fuel-check-night-web\` の書き込み権限が必要（現状、所有者アカウントのみアクセス確認済）。
- 一般利用者は登録済み店舗から選ぶだけ。POS入庫カードの名前／選択番号は各端末で変更可能。担当者コードも各端末で管理し、公開GitHubには入れない。
- 管理者が登録する項目は店舗名、タンクNo.、容量、油種。H/R/D・Kの数値判定基準は油種で自動選択し、その他の油種は正式な基準値を管理者が確認してから登録。カード名称・選択番号と担当者指定方法は利用者の各スマホで登録する。
- 過去にスマホのブラウザだけで作った未承認店舗、古いLINE店舗共有リンクは正式店舗として読み込まれない。保存済みの伊都店の数字は保持。
- 暗証コードをJavaScript内に書くだけでは誰でも閲覧・回避できるため、公開アプリには管理者用の暗証コードを設けない。認証はGitHubアカウントの書き込み権限に依存する。
- この仕組みは「サイトに正式登録する権限」を制限するもの。利用者が自分のブラウザの表示を改変する行為まで防止するログイン式のシステムではない。

## 店舗ごとの担当者指定方式（2026年11月2日）
- 店舗のPOSにより、担当者コードを数字で入力する方式と、POS画面の「担当者」ボタンから「夜勤」等の名前を選ぶ方式がある。
- 店舗を選ぶだけで表示が切り替わり、上部フローと工程6、参考画面で同じ方式を案内する。
- フロー上部「担当者の指定 → 店舗別に設定」で「担当者コードを入力する」または「担当者ボタンから選択する」を選び、後者はボタン名（例：夜勤）を入力する。
- 設定は店舗ごと・スマホごとの localStorage。以前登録した伊都店の数字コードは維持。他店舗へは引き継がれない。公開店舗リストやLINE URLには含まれない。
- ボタンの実際の文言・操作順は各店舗のPOS画面で確認し、使用権限のある担当者が操作する。
